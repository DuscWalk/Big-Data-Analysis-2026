## 3. 环境与运行准备

日常命令、文件和 Git 操作以 `duscwalk` 执行，项目 Python 使用 Conda `AgentDev`。选环境的命令已可使用：

```bash
source /home/duscwalk/miniconda3/etc/profile.d/conda.sh
conda activate AgentDev
```

当前已安装基础 Python 环境与项目依赖，具体版本、锁文件和运行命令见 [环境指南](../../development/environment.md)。解释器检查命令为：

```bash
test -x "$CONDA_PREFIX/bin/python" && "$CONDA_PREFIX/bin/python" -c 'import sys; print(sys.executable); print(sys.version)'
```

选择环境与依赖安装分别记录；不会把空环境回落到系统解释器时的包列表登记为项目依赖。依赖安装后维护项目配置与复现清单，具体启动命令在实现完成且实际跑通后加入 README。

运行准备按以下顺序验收：

| 检查 | 可复核结果 |
| --- | --- |
| Python 与项目依赖 | 解释器位于 AgentDev，声明依赖可导入，实际版本有记录 |
| Hadoop 与 JDK | 版本兼容性说明；用户身份正确；HDFS 可读写；Streaming 使用目标解释器成功执行 |
| 原始数据 | 三文件存在，校验值匹配登记版本，解析配置可读取 |
| 元数据与工作目录 | 应用和 worker 可写，正式结果与临时结果隔离，生成文件不会进入 Git |
| 模型适配 | 实际模型能返回可校验的工具调用，失败时说明原因，查询与证据返回可运行 |
| 应用与 worker | HTTP 接口、页面及后台任务机制连通；页面刷新可重新查询已受理任务 |

Hadoop 初始化脚本需区分首次准备与已有数据启动，不能在每次启动时格式化 NameNode 或清空产物目录。停止页面或 API 与停止 Hadoop 作业是不同操作，运行文档应分别说明。

## 4. 验证层次与证据

| 层次 | 验证重点 | 证据与边界 |
| --- | --- | --- |
| 规则与指标 | 已知重复、冲突、缺失、非法时间、孤立引用、零分母及前后统计 | 人工可核算的小样例；明确为验证材料，不混入正式数据 |
| 框架集成 | 工具注册、结构校验、精确版本、请求去重、任务发布、失败恢复、会话隔离 | 针对关键行为的调用与状态记录；测试替身不用于证明真实 Hadoop 或模型可用 |
| 实际组件接入 | 模型真实工具调用、HDFS/Streaming、单 worker、页面与查询 | 实际版本、命令或配置摘要、作业标识、日志和结果引用 |
| 全量业务 | 原始三表的前评分、清洗、后评分与报告 | 输入校验值、规则/评分版本、时间边界、原始计数、处置守恒、运行耗时及限制 |
| 扩展与交接 | 新工具接入、旧结果读取、另一位成员复现 | 新增工具代码位置、注册方式、实际调用和通用页面显示 |

`datasets.describe` 可以先作为公共框架开发样例，之后在独立的扩展验收中由另一位成员按文档重新接入验证；若已成为内置工具，则选择另一个读取真实登记信息的查询工具，不能只看已有硬编码分支便宣称通过扩展验收。

每份验收记录至少写明需求编号、输入版本、配置/代码版本、实际步骤、预期行为、实际结果、证据位置和未解决问题。只有正式环境和实际数据跑通后才把业务项标记完成。
