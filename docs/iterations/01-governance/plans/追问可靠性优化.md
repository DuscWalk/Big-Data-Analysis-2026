## 2. 实施范围与设计

### 应用先准备本轮必需证据

对绑定到已完成治理任务的请求，应用通过现有工具注册表读取精确质量 summary，核对产物哈希并持久化调用，再向模型提供精简的解释依据。明确指定的异常规则或清洗文件样例也由应用预读。预读与模型主动查询共用参数校验、会话范围、请求键和调用记录；不伪造一次模型调用。

模型上下文标明哪些证据由应用取得。原始完整工具返回保留在审计记录中，模型只接收解释需要的要点、可用样例及来源标识。模型仍可查询额外证据，发起新任务仍沿用既有工具机制。

### 持久化当前问题的回答要求

从明确的请求约束提取主题、完整/简短偏好、样例类型、规则或文件及数量，随回答 validation 保存。首版支持治理领域明确的中文/英文表达及组合问题；不能声称完成通用自然语言理解。对含糊指代保留最近同任务的有限历史，仍由模型解释；不把整段历史答案当作当前事实。

运行时检查样例是否属于本轮、规则/文件是否匹配、数量是否符合要求，要求的解释主题是否覆盖，以及简短回答是否超出范围。没有样例时明确返回当前证据未提供样例，不能编造记录。缺少必需要点或超限时允许一次有界修正，仍不满足则明确失败，不静默返回答非所问的成功结果。

### 精简事实呈现与上下文

保留原报告和已登记的数值，提供简短事实段落及有来源的样例呈现；按所问维度缩小解释范围。简短回答以不超过 800 个字符、最多 4 个普通要点为默认约束；复合问题确需更多主题时由明确要求决定并记录，不能截断关键证据。样例数以明确请求为准，未指定时默认 1 条，遵守工具上限。

完成任务的追问只使用最近同任务的少量历史，并省略过长的历史答复。模型输入不重复携带同一报告的完整结构化计数和全部解释副本。通用调用循环负责审计和调用预算；治理领域的主题识别与文字规则留在治理/解释模块，后续算法可接入自己的证据策略。

## 4. 验收方法

### 稳定的行为验证

- 使用小数据和模型替身核对：应用先取证、完整调用记录、原始用户问题保留、工具错误、错误版本、会话隔离、幂等缓存和新任务受理。
- 用真实失败回答的同类计划验证：样例已读取却不展示、错误规则/文件、数量不符、借用旧样例、遗漏主题、简短回答选择整份报告均不能成功通过。
- 验证正常路径：完整报告、单主题、复合追问、明确数量、无样例、未知问题、有限修正、历史指代和普通工具循环。
- 运行普通测试、JavaScript 语法、文档链接及 Git 差异检查。不为文档或样式变更新增无意义测试。

### 实际模型与页面验证

固定 `MODEL_PROVIDER=backup`、`deepseek-v4-flash`，使用任务 `064523f8a8bf41a38f7c2193caf59930` 的已有精确产物。完整解释、原因重叠、时效性单位、时间分区、无法证明的结论、异常样例、简短复合追问各重复 3 次，使用新的请求 ID，确认任务数不增加。

记录首次业务通过率、遗漏/超长次数、实际 provider、模型轮数、输入 token、时延及应用修正次数。目标是三轮内不出现成功返回的样例遗漏或超长回答；网络故障与回答内容失败分开统计，所有失败保留。若模型仍不稳定，应报告未达标项并继续定位，不以更换题目、隐去失败或无限重试得到通过结论。

最后启动 API，用实际新追问检查回答标签、调用依据、validation 和刷新持久性；普通页面检查复用已有真实任务，不额外提交治理任务。

## 5. 风险与边界

- 明确约束提取有适用范围，否定表达、多主题与含糊指代需要测试，避免把关键词误当用户指令。
- 简短呈现不能删除关键单位、限制或来源；完整报告与原始工具记录保留。
- 预读是当前请求的真实工具调用，不能冒用历史摘要或写成模型自主调用。
- 修改前确认没有排队、运行中的任务或处理中的消息；独立回归与 API 继续使用同一把进程锁。
- 不增加依赖、修改课程原文、迁移已发布产物或改写旧回答。成员独立复现与汇报演练仍由原交接计划跟踪。
