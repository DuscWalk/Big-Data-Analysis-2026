# 迭代一：数据与评分约定

**状态：首版规则、公式与时间参数已实现，通过手算样例与真实 Hadoop 全量验证。** 实际 Hadoop 验证与全量结果由[开发计划](开发与交接计划.md)记录。默认配置见 [default.json](../../../configs/governance/default.json)，处理实现见 [streaming.py](../../../src/movielens_agent/governance/streaming.py)。本方案是小组依据[原始核查](reports/2026-09-24-原始数据核查.md)确定的实验口径，不是课程指定公式。

## 1. 输入、版本与来源

原始数据保持只读。三表按 ISO-8859-1、无表头、`::` 解析；空行与没有末尾换行的末行均计一条物理记录。处理前核对登记的 SHA-256、字节数与行数，并检查封装期间文件是否变化；不一致则失败，不能沿用旧版本。

应用只将每条原始记录封装为 UTF-8 JSONL：原始字节以 Base64 保存，附 `table` 和 `source_ref`（输入版本、文件、字节偏移、行号）。此步骤没有业务过滤或修复。正式解析、规则、分组、清洗及五维计算全部由 Hadoop Streaming 完成。

ISO-8859-1 解码成功不证明文本正确。疑似混合编码保留原值和警告，不进行推测性转换。任务记录规则、评分、时间分区的独立内容哈希及实际执行代码哈希；配置先校验，再在受理时固定快照。

## 2. 清洗数据协议

输出为 UTF-8 JSONL，所有记录带原始 `source_ref`，没有表头。数字规范化为整数，邮编保持字符串。

| 表 | 业务字段 |
| --- | --- |
| users | user_id、gender、age_code、occupation_code、zip_code |
| movies | movie_id、title、genres（去重、排序的字符串列表） |
| ratings | user_id、movie_id、rating、timestamp（Unix 秒） |

年龄代码保留类别含义，不当作真实年龄。评分业务键为 `(user_id, movie_id, timestamp)`；不同时间的事件均可保留。最大 ID 或官方数据总数不充当本地副本的有效性阈值。

发布的清单包含三表文件、编码/格式、行数、SHA-256、任务、输入引用、配置引用、时间边界和分区数量。精确产物引用始终是 `artifact_id + version`。本地已核对的三表同时上传到任务专属 HDFS 数据目录，后续工具从已发布清单解析位置。

## 3. 默认规则与处理顺序

**先隔离确定非法的候选，再判断剩余候选是否同键冲突。** 原始核查发现不少冲突包含非法类别或非法评分；把这些候选先排除，可以避免它们污染合法候选。对仍然冲突的合法候选，没有可信依据时全部隔离，不以文件顺序猜测真值。

| 编号 | 条件与行为 |
| --- | --- |
| R01 | 字段数错误（包括空行）：隔离 |
| R02 | 任一必需字段为空：隔离 |
| R03 | 字段首尾空白：去除，记录修改前后值 |
| R04 | ID 非整数或不在 1 至 2^63−1：隔离 |
| R05 | 性别不在 F/M、年龄代码不在 1/18/25/35/45/50/56、职业代码不在 0—20：隔离 |
| R06 | 电影类型为空或有源说明 18 类之外的值：隔离 |
| R07 | 类型集合去除重复项、条目首尾空白并排序：记录规范化 |
| R08 | 评分非整数或不在 1—5：隔离 |
| R09 | 时间戳非整数秒、为负数或超出 UTC 9999-12-31 23:59:59：隔离 |
| R10 | 时间戳不在固定历史区间：隔离 |
| R11 | 可确定的整数写法，如 01、+5：规范化并记录原值 |
| R12 | 评分引用不存在的主表实体：隔离；区分原始缺失与主表清洗后移除 |
| R13 | 原始评分引用冲突的原始主表实体：一致性检查不通过 |
| R14 | 合法候选仍有同键不同属性/评分：全部隔离 |
| R15 | 合法候选同键同值：保留源文件中偏移最小的一条，其余去重并指向保留来源 |

正式顺序：原始主表检查 → 原始评分检查 → 前评分汇总 → 清洗主表 → 清洗评分及重新关联 → 清洗后三表检查 → 后评分与处置汇总。共七个 MapReduce 作业，应用随后核对输出并发布。

邮编格式异常、标题无末尾年份、疑似混合编码仅作警告。高频评分、同名电影和历史较久不自动触发删除。没有训练统计量填补或从验证/测试数据推断的冲突消解规则。

每条输入的最终处置互斥：

- `kept`：保留且没有业务规范化。
- `repaired`：保留并进行了可确定的规范化；不能宣称核验了真实性。
- `deduplicated`：同键同值的多余候选，指向保留来源。
- `quarantined`：无法可靠使用，保留原字节与原因。

处置明细保存原内容、来源、规则、警告、变换历史及保留引用。先规范化再隔离的记录最终仍算隔离。必须满足：

```text
input_rows = output_rows + deduplicated_rows + quarantined_rows
output_rows = kept_rows + repaired_rows
```

问题标签可能重叠，不能将标签次数相加当作移除量。Hadoop 计算处置统计，应用独立核对导出条数、守恒与外键；不通过则不发布。

## 4. 五维公式

每个比例记录 `passed`、`population`、`score` 和状态。分数为 `100 × passed / population`；分母为零时为 `null/not_evaluable`，附原因，不给 0 或 100。

| 维度 | 分子 / 分母 | 边界 |
| --- | --- | --- |
| Accurate | 通过的值约束项 / 每行固定的检查项数 | ratings 每行检查评分 1 项；users 检查性别、年龄、职业 3 项；movies 检查非空且全合法的类型集合 1 项 |
| Complete | 非空必需字段槽位 / 期望槽位 | 三表每行分别为 5/3/4 个槽位；字段数错误的行分子为 0，分母仍计全量槽位 |
| Unique | 不同可构造的业务键 / 全部输入行 | 实体键为正整数 ID；事件键含正整数 ID 和可表示的非负整数时间戳；2100 年时间能构造键，但历史范围检查不通过 |
| Up-to-date | 固定闭区间 `[reference_time-window_seconds, reference_time]` 内的评分行 / 全部评分行 | 未来时间不新鲜；users/movies 无事件时间，标为 not_applicable |
| Consistent | 结构、必需值、值域、历史时间、同键冲突及适用外键检查均通过的行 / 全部行 | 原始数据基于原始主表；清洗后基于清洗主表，前后适用同一逻辑 |

Accurate 明确称为“可验证值约束代理”，不能证明用户属性或电影事实真实。各维度可能反映同一异常，不具有相互独立的错误数量含义。

原始冲突按所有可构造业务键的记录判断，非法候选也会造成前评分冲突；只有清洗阶段采用“先排除非法候选”。原始主表中可构造键但属性非法的单一实体仍算存在，评分外键检查单独判断存在性与冲突；清洗后重新检查发布候选主表。

先保留分表结果，再对 Accurate、Complete、Unique、Consistent 按三表等权求均值；Up-to-date 只取 ratings。任一必需表为空时，前四项汇总不可评价，不重新分配权重。没有额外综合分。

前后固定公式、检查项、时间参照和权重。必须一起呈现分子、分母、输入/输出、隔离/去重/修复；隔离导致的满分不等于丢失信息已修复。应用只读取 Hadoop 分数和计算显示用差值，不在 Hadoop 之外替代正式评分。

## 5. 历史时间与 T1/T2

GroupLens [官方页面](https://grouplens.org/datasets/movielens/1m/)标记 MovieLens 1M 发布于 2003 年 2 月，随附 README 说明入选用户于 2000 年加入。首版选取以下固定历史场景，而非使用被 2100 年异常污染的最大时间戳：

| 配置 | UTC | Unix 秒 |
| --- | --- | ---: |
| 允许事件下界（含） | 2000-01-01 00:00:00 | 946684800 |
| 允许事件上界 / 时效参照（含） | 2003-02-28 23:59:59 | 1046476799 |
| 时效窗口 | 回看 365 天（两个端点均包含） | 31536000 |
| T1 / train_end | 2000-11-30 23:59:59 | 975628799 |
| T2 / validation_end | 2000-12-31 23:59:59 | 978307199 |

精确日界是小组的保守日历约定，不声称来源提供了秒级采集边界。核查显示有效事件主要集中于 2000 年，另有 2001—2003 年数据，因此用 11 月末/年末形成按时间顺序的三段；未按模型得分或测试标签挑选边界，不保证固定 8:1:1 比例。报告交付实际分区数量。后续若改变场景或边界，必须升配置内容版本并生成新的引用，不能混用已有结果。

```text
train:      timestamp <= 975628799
validation: 975628799 < timestamp <= 978307199
test:       timestamp > 978307199
```

当前仅登记过滤条件，未物化三个文件。后续训练须先按 T1 过滤；学习型填补、特征与阈值只在训练期拟合。时效分数只表达此历史快照下的 365 天窗口覆盖率，不代表相对于 2026 年的新鲜程度，也不是删除旧评分的条件。

## 6. 结果与发布

必需产物为清洗数据、质量 JSON、处置 JSONL 和 Markdown 报告；只有文件校验、守恒与外键验证通过后，才在一个 SQLite 事务中登记全部产物并将任务标为 succeeded。失败或未确认状态不会发布部分结果。

质量 JSON 含配置快照、分表与汇总指标、实际分子/分母、处置/警告/变换次数、时间分区和作业标识。代表样例按表及规则保留最多 3 条，完整处置明细单独保存。空数据的诊断可以发布，但不能视作正常数据验收，清单会标明不可用于训练。

完整运行步骤见[环境指南](../../development/environment.md)；整体工具与任务约定见[技术方案](技术方案与接口约定.md)。
