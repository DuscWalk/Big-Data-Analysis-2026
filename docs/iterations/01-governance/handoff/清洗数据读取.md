# 清洗数据交接与下一轮读取

本页交接一个已经通过七作业 Hadoop 治理的**精确版本**，并给出可直接运行的读取程序。它不需要启动模型、API 或 Hadoop，也不会重新清洗。机器可读引用与三文件摘要见 [dataset-reference.json](dataset-reference.json)；生产过程见[全量 Agent 联调报告](../reports/2026-09-25-Agent联调实测.md)。

## 1. 准备文件与环境

代码当前在 `feat/iteration-01-foundation` 分支；先按[环境指南](../../../development/environment.md)准备 AgentDev 并安装项目，再取得以下四个文件，放在同一个目录：

```text
var/handoff/iteration-01/
├── dataset-manifest.json
├── users.jsonl
├── movies.jsonl
└── ratings.jsonl
```

本机已有目录为 `var/runs/33ce0c793b6e4d92acb6400cd96b3faa/published/`。可从该目录复制四文件，或在实际会话的下载区逐一获取；文件不随 Git 同步。重跑会生成不同 task/artifact ID，不能把重跑清单与这里的旧引用混用。

读取器只使用清单中的文件名，在清单旁寻找数据；不使用清单内生产机器的绝对路径，也不要求访问 HDFS。保留清单原文即可搬到其他目录。

## 2. 精确引用与读取命令

| 项目 | 交接值 |
| --- | --- |
| 生产任务 | `33ce0c793b6e4d92acb6400cd96b3faa` |
| 清洗产物 ID | `33ce0c793b6e4d92acb6400cd96b3faa.cleaned` |
| 版本 | `sha256-b64d8d8e78e93a796ac86342e19a3a3b2d9316a6c89f3e930defe190375f1213` |
| users / movies / ratings | 5,895 / 3,836 / 935,354 行 |
| 存储 | UTF-8 JSONL；三张完整清洗表，按时间过滤分区 |

在仓库根目录运行；本机可将第一行目录改为已有 `published/` 路径：

```bash
MOVIELENS_DATA_DIR=var/handoff/iteration-01
python scripts/examples/read_cleaned.py \
  --manifest "$MOVIELENS_DATA_DIR/dataset-manifest.json" \
  --task-id 33ce0c793b6e4d92acb6400cd96b3faa \
  --artifact-id 33ce0c793b6e4d92acb6400cd96b3faa.cleaned \
  --version sha256-b64d8d8e78e93a796ac86342e19a3a3b2d9316a6c89f3e930defe190375f1213 \
  --split train
```

期望训练计数为 **746,139**；将最后一项改为 `validation`、`test`，分别得到 **100,814**、**88,401**。命令先核对清单内容哈希、任务/产物引用、配置引用和三文件 SHA-256，再流式读取所选分区，输出计数和最多三行带来源的样例。完整遍历后核对实际分区数；一次读取不把全表载入内存。

读取器拒绝错误版本、被改写或缺失的文件、未标记为可用于训练的数据，以及隐式 `all` 分区。独立传入的固定引用应来自交接记录，不要从待验证清单读出一个新 version 就直接信任它。每次读取会在同一已打开文件上重新校验哈希；计算期间仍应保持交接文件只读。

## 3. 时间边界

| 分区 | 时间条件（UTC，Unix 秒） | 行数 |
| --- | --- | ---: |
| train | `timestamp <= 975628799` | 746,139 |
| validation | `975628799 < timestamp <= 978307199` | 100,814 |
| test | `timestamp > 978307199` | 88,401 |

T1 为 `2000-11-30T23:59:59Z`，T2 为 `2000-12-31T23:59:59Z`。T1 属于训练，T2 属于验证。分区条件和计数已经登记，**没有独立的 train/validation/test 文件**；读取器直接过滤 `ratings.jsonl`。

标准化、词表、用户历史画像、聚类中心和降维变换等只在训练分区拟合；验证用于选择参数，测试用于最终评价。分类标签为 `rating >= 4`，不能把当前事件的 rating 或验证/测试期统计当作训练特征。用户年龄、职业仍是类别编码，邮编保留字符串。该读取器负责版本和时间过滤，不替代下一轮算法的数据泄漏审查。

## 4. Python 接入

可复用实现为 [storage/cleaned.py](../../../../src/movielens_agent/storage/cleaned.py)，命令行例子为 [read_cleaned.py](../../../../scripts/examples/read_cleaned.py)。例如仅用训练期事件统计用户活跃度：

```python
from collections import Counter
from movielens_agent.contracts import ArtifactRef
from movielens_agent.storage.cleaned import CleanedDataset

data = CleanedDataset(
    "var/handoff/iteration-01/dataset-manifest.json",
    expected_task_id="33ce0c793b6e4d92acb6400cd96b3faa",
    expected_ref=ArtifactRef(
        artifact_id="33ce0c793b6e4d92acb6400cd96b3faa.cleaned",
        version="sha256-b64d8d8e78e93a796ac86342e19a3a3b2d9316a6c89f3e930defe190375f1213",
    ),
)
data.verify()
training_activity = Counter(event["user_id"] for event in data.ratings("train"))
users = {row["user_id"]: row for row in data.entities("users")}
print(len(training_activity), len(users))
```

`ratings(split)` 返回生成器；处理一行后即可交给下游，不要默认转成包含全部评分的列表。正常完成迭代才会执行末尾的行数检查；提前中断仍完成了读取前的文件哈希校验，但不能声称通过全量行数验收。

新算法工具的输入应要求完整的 `ArtifactRef` 和 `config_refs.split`；从当前会话的已发布清单解析文件，用这里的读取器加载。训练产物至少记录清洗引用、split 引用、训练截止时间、算法/特征参数及实际评价分区。长任务沿用 TaskStore、worker 和原子发布，具体接入见[任务与工具指南](../../../development/tasks-and-tools.md)，不要在 Agent 分发器里添加算法专用分支。
