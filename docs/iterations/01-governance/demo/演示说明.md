## 3. 可直接复制的追问

确认左侧选中上述已完成任务。将下面的问题**分别发送**，每次等上一条结束。

### A. 时效性：推荐第一问

```text
请只解释本任务时效性：给出实际分子、分母、正确分数、百分比及历史窗口，不要重新清洗。
```

核对要点：清洗后 `20,208 / 935,354 × 100 = 2.160465` 分（百分比为 2.160465%）；不能说成 216 分，也不能将历史数据旧当作清洗失败。模型应解释本任务固定的历史参照与窗口。回答下方显示“报告事实 · 要点选择模型”，点击“查看调用依据”可查看当前报告读取；其中 `application` 表示应用取证，`model` 表示模型主动查询。

### B. 来源样例与连续追问

先发送：

```text
请读取一个 ratings/R14_VALID_KEY_CONFLICT 的实际异常样例，保留原始行、处置结果和来源定位。只查看已有结果。
```

核对要点：第一条包含原始行 `26::2628::1::978143313`，处置 `quarantined`，以及 `ratings.dat` 第 23 行、字节偏移 545 和原始数据版本。它属于同键评分冲突；不要据一条样例推断所有被隔离评分的原因。

这一问成功后，紧接着发送：

```text
再给一个。
```

应继续同一规则下一条样例，保留新的来源位置。两条问题之间不要插入其他统计问题或切换任务，否则“再给一个”的指代可能需要重新明确。若开场样例问题失败，先重试该问题，成功后再继续。

### C. 时间充裕时选问：满分与真实性

```text
四项满分能证明数据真实吗？为什么时效性低？请简要说明，不要给样例。
```

应说明满分只代表保留记录通过已实现约束；无法核验用户真实年龄、电影属性或保证后续分类效果。简短回答不应变成完整报告。

### D. 时间充裕时选问：损失与统计口径

```text
请读取实际证据，解释评分减少的原因，并说明父表引用问题的原因命中次数能否直接相加作为受影响行数。不要重跑任务。
```

核对要点：评分隔离 214,887 行，评分去重为 0；父表引用问题 89,939 是可重叠的原因命中次数，不是互斥的记录数。

10 分钟演示推荐 A、B，C/D 留作答疑。已有会话保留了开发中的失败和旧版回答；现场新提问使用当前策略，不将旧自动解释缓存当作刚刚生成的答复。

## 5. 从空会话发起一次完整任务

适合演练时提前执行，或专门展示“受理与执行”的环节。每次发送下面的请求会创建一个新的真实 Hadoop 任务，通常需十余分钟完成。

1. 在另一个标签页打开应用首页，点击右上角“新建会话”，保留页面生成的会话链接。
2. 发送：

```text
请使用默认规则清洗 MovieLens 1M，评估前后五维质量，并说明处理的问题与局限。
```

3. 看到“已受理任务”及任务 ID 后，左侧会自动刷新阶段。“受理”表示入队，不代表计算完成；不要为等待结果反复发送清洗请求。
4. 等左侧显示“已完成”，查看五维评分、三表处置、报告与自动解释。若自动解释失败，已发布数据仍可查看，按第 6 节处理。
5. 围绕**新任务**继续提问；不要把第 4 节已完成任务的数字直接当成新任务结果。

本次启动服务没有执行此步骤，也没有创建新的治理任务。若现场新任务还在执行，可切回第 1 节的历史会话，明确说明接下来展示的是提前完成的另一次运行。

## 6. 失败时如何继续演示

| 现象 | 操作与说明 |
| --- | --- |
| 模型返回 502/504 或超时 | 说明本次解释未完成。使用失败消息下的“查看该任务报告”，继续展示实际指标、样例和下载；如需再试，点击一次“重新解释此问题” |
| 重试后成功 | 指出生成了新的回答，原失败记录保留；原问题、任务和样例位置不变，也不会重提清洗任务 |
| “需要明确问题范围” | 指定规则或文件，例如“再给一个评分冲突样例”；不要把正常澄清讲成模型或 Hadoop 故障 |
| 报告中没有更多样例 | 说明报告仅保留有限代表样例；当前规则只有 3 条，不能由空页推断全量没有异常 |
| 任务为“状态待核查” | 展开阶段并核对外部作业与日志，不宣称完成，不直接连续重跑；切到已完成任务说明目前的恢复边界 |
| 页面打不开 | 按第 7 节查看 API 状态；不要重新初始化 Hadoop 或删除已有数据 |

可用的收尾说明：

> 四项高分仅代表约束检查通过，真实属性仍有不能核验的部分。模型服务可能超时，但已发布数据和报告不依赖模型继续可读。当前支持有明确来源的治理追问，复杂表达仍有边界；中断任务需要核查外部状态。
