# MovieLens 质量评分计算规则

更新日期：2026-09-30。本文说明当前程序如何从记录计算五维质量分数，包括分子、分母、汇总、边界和完整算例。具体记录处置见[清洗规则](清洗规则.md)。这是小组制定的实验评价口径，并非课程指定的唯一公式。

文中的“默认”指仓库初始方案。网页共享默认可以修改，解释某次报告时以任务保存的配置快照为准。下文算例为构造的小样本，已用实际评分与清洗函数核对，不是课程全量统计。

## 1. 先理解分数在衡量什么

系统分别计算准确性 `Accurate`、完整性 `Complete`、唯一性 `Unique`、时效性 `Up-to-date`、一致性 `Consistent`，**没有把五个维度再合成一个总分**。

每个可计算的分表指标使用同一基本形式：

```text
分数 = 100 × 通过数量 passed / 评价总量 population
```

“数量”的单位随指标变化，可以是字段检查项、字段、不同业务键或记录。不是每发现一项错误就从 100 分扣固定分数。

- 清洗前：分母包含原始文件全部物理行，包括空行和字段数错误行。
- 清洗后：只对实际保留的 `kept + repaired` 记录重新计算，隔离和去重记录不进入后分母。
- 同一任务前后使用同一份评分与清洗配置。各维度独立计算；某行评分越界，不意味着它的完整性、唯一性或时效性一定也不通过。
- 原始数据在评分时也会先去字段首尾空白、解析可识别整数等。因此评分反映规范化后能识别的约束，不是原始文本格式整洁度。

## 2. 五维公式速查

令 `N_users`、`N_movies`、`N_ratings` 为本次评价视图中各表的行数：前评分用原始行数，后评分用保留行数。

| 维度 | 分子 | 分母 | 适用表 |
| --- | --- | --- | --- |
| Accurate | 通过值域检查的检查项数 | users 为 `3N`，movies、ratings 为 `N` | 三表 |
| Complete | 字段数正确的行中，去首尾空白后非空的字段数 | users 为 `5N`、movies 为 `3N`、ratings 为 `4N` | 三表 |
| Unique | 可构造的不同业务键数量 | `N` | 三表 |
| Up-to-date | 类型合法且落在闭区间 `[参照时间−窗口秒数, 参照时间]` 的时间戳对应行数 | `N_ratings` | 仅 ratings |
| Consistent | 没有行级错误，且不处于同键冲突组中的行数 | `N` | 三表 |

所有公式均再乘 100。分母为零时不执行除法，状态见第 8 节。

## 3. 准确性 Accurate：值域约束通过率

### 3.1 每张表检查什么

| 表 | 每行检查项 | 计算方式 |
| --- | --- | --- |
| users | 性别为 `F/M`；年龄代码属于 `{1,18,25,35,45,50,56}`；职业代码为 `0—20` 的整数 | `100 × 三项检查通过总数 / (3 × N_users)` |
| movies | 类型非空，且拆分后的全部类型均在允许的 18 类中 | `100 × 类型检查通过行数 / N_movies` |
| ratings | 评分是 `1—5` 的整数 | `100 × 评分检查通过行数 / N_ratings` |

电影类型集合的检查是**每行一项**，不是按类型个数累计。例如 `Drama|Unknown` 整项失败，不给一半通过量。允许的 18 类见[清洗规则第 5 节](清洗规则.md#5-电影表规则)。

用户一行只有职业非法时，准确性贡献为 `2/3`；并不要求一行全部合法才累计通过项。`+5` 等可明确解析的整数按数值判断，`4.5` 不算合法整数评分。

字段数错误会使解析提前结束：该行通过数为 0，但仍贡献整行应有的检查项分母。空用户行增加 3 个分母，空评分行增加 1 个。

### 3.2 不包含哪些含义

ID、时间、外键、邮编格式、标题年份均不直接进入 Accurate 的检查项。评分是 `5` 但用户不存在，可以通过 Accurate，同时无法通过 Consistent。

该指标不验证事实真伪：用户真实年龄、电影真实类型、用户是否真的打过该分，都没有外部可信数据源核验。报告中的“准确性 100”只表示上述值域检查全部通过。

## 4. 完整性 Complete：必需字段非空率

三表分别应有 5、3、4 个字段。字段数正确时，对每个去掉首尾空白后的非空字段计 1；空字段计 0。

```text
Complete_users   = 100 × 非空字段数 / (5 × N_users)
Complete_movies  = 100 × 非空字段数 / (3 × N_movies)
Complete_ratings = 100 × 非空字段数 / (4 × N_ratings)
```

例如评分行 `1::1::::978307200` 有 4 个字段，其中评分为空，贡献 `3/4`。`1::1::abc::978307200` 四个字段都有内容，贡献 `4/4`，尽管评分无法解析。

**字段数不正确的整行，非空贡献为 0**。程序不猜测这些片段对应哪些字段；例如只有三个片段的评分行贡献 `0/4`，不是 `3/4`。`Drama|` 的类型字段非空，完整性仍通过，但准确性不通过。

清洗没有填补缺失值。清洗后完整性升高，可能是缺失记录被隔离，而非缺失信息被恢复。

## 5. 唯一性 Unique：不同业务键占比

```text
Unique_table = 100 × 不同的可构造业务键数量 / 该表全部行数
```

| 表 | 业务键 | 构造条件 |
| --- | --- | --- |
| users | `user_id` | 字段数正确，ID 是 `1—2^63−1` 的整数 |
| movies | `movie_id` | 字段数正确，ID 是 `1—2^63−1` 的整数 |
| ratings | `(user_id, movie_id, timestamp)` | 字段数正确，两个 ID 合法，时间是 `0—253402300799` 的整数秒 |

时间是否在允许历史区间内，不影响键能否构造。例如类型合法的 2100 年评分时间可以参与 Unique，但在初始清洗方案中会因超出允许区间被隔离。评分值本身非法，也不必然妨碍键的构造。

同键出现两次或十次，分子都只加 1；同键同值和同键不同值都按一个不同键计数。无法构造键的行只增加分母、不增加分子，也不会把所有坏键合并成一个虚构实体。

例如三条同键记录的评分为 `5、5、9`，该组对 Unique 贡献 `1/3`，而非只把完全重复的一条当问题。不同时间的评分属于不同事件，不会因用户与电影相同就扣唯一性。

## 6. 时效性 Up-to-date：指定观察时点的窗口覆盖率

令 `R = metrics.reference_time`，`W = metrics.window_seconds`：

```text
Up-to-date_ratings = 100 × 满足 R−W ≤ timestamp ≤ R 的时间类型合法行数
                          / 全部评分行数
```

初始值：

| 参数 | 值 |
| --- | --- |
| 参照时间 R | Unix 秒 `1046476799`，即 UTC `2003-02-28 23:59:59` |
| 窗口 W | `31536000` 秒，即 365 天 |
| 窗口下界 R−W | Unix 秒 `1014940799`，即 UTC `2002-02-28 23:59:59` |

两端都包含。早于下界不通过，晚于参照时间也不通过。空行、错误字段数和非法时间仍进入全部评分行分母，但不贡献分子。

R 是小组为历史数据选定的观察时点，**不是数据中最新时间，也不是系统当前时间**。它回答的是“在这个历史时点看，有多少评分属于最近 365 天”，不回答“数据今天是否仍然新鲜”。

配置校验要求 R 为 `0—253402300799` 的整数秒，W 为正整数秒且 `W ≤ R`，避免窗口下界早于 Unix 纪元。旧版 `metrics-v1` 还要求 R 等于清洗允许时间上界；`metrics-v2` 解除这一绑定。

时效检查独立于评分值、ID、外键和清洗允许时间区间。只要字段数正确、时间类型合法且落在窗口内，即便评分值是 `9`，该行仍可贡献时效分子。

允许事件区间决定是否隔离；时效窗口决定是否算“近期”。两者不能混用。`metrics-v2` 可以独立配置 R 和 W；更改窗口会改变衡量标准，应同时展示参数，不能据此声称数据本身得到了改善。

users 和 movies 没有本方案需要的事件时间，时效性标记为 `not_applicable`，不是 0 分。整体时效性直接采用 ratings 的分数。

## 7. 一致性 Consistent：行级规则与同键相容性

```text
Consistent_table = 100 ×（无行级错误且所在业务键组无冲突的行数）/ N_table
```

行级错误包括字段数、必需字段、ID、值域、时间类型、允许时间区间、评分外键，以及已开启的三项可选隔离策略。仅有警告或可确定的规范化，不会自动成为一致性错误。

分组冲突按规范化后的字段比较：同一个可构造业务键下出现不同属性或评分，该组有冲突，该组所有行的一致性贡献为 0。整数写法或类型排序不同但规范化结果相同，不算冲突。

需要区分三个细节：

1. **完全相同的重复记录可以都通过一致性。** 两条合法同键同值评分，Consistent 可以是 `2/2`，Unique 为 `1/2`。
2. **前评分检查整个原始组，清洗先移除非法候选。** 原始同键评分 `5、9` 因签名不同而冲突，两条前一致性都不通过；清洗先隔离 `9`，合法的 `5` 仍可保留并在后评分通过。
3. **外键按当前视图判断。** 前评分查原始主表的存在与冲突；后评分查保留主表。原始 ID 存在但属性非法的用户，可能先满足存在性检查，清洗移除后再触发关联评分的连带隔离。

三个可选开关主要影响行级一致性与清洗接收策略，不增加 Accurate、Complete 等维度的检查项，但会通过改变保留记录间接改变后评分。疑似混合编码检测针对原始电影标题字节，重新评分结构化清洗记录时不再执行原字节探测；原警告仍在处置证据中。完整条件见[清洗规则第 8 节](清洗规则.md#8-三个可配置隔离开关)。

## 8. 空表与不可计算状态

| 情况 | score | status | 含义 |
| --- | --- | --- | --- |
| 分母大于零，正常计算 | `0—100` | `computed` | 0 分也是有效计算结果 |
| 适用该指标，但该表没有行 | `null` | `not_evaluable` | 没有评价样本，不记 0 或 100 |
| users/movies 的时效性 | `null` | `not_applicable` | 缺少此指标需要的业务时间，不适用 |

如果清洗把一张表全部隔离，不能报告“清洗后满分”。四个三表维度的整体汇总也会因缺少必要分表结果而标记不可计算，不会忽略空表后把其余表的权重重新分配。

## 9. 从三张表汇总到报告的五维结果

### 9.1 初始等权方案 metrics-v1

对 Accurate、Complete、Unique、Consistent，先算每张表分数，再计算：

```text
整体某维分数 = (users 分数 + movies 分数 + ratings 分数) / 3
```

不是把三表所有分子和分母混在一起算；也不是按三表行数加权。这样评分表虽然大，也不会在汇总中完全盖过用户表、电影表的问题。

### 9.2 可配置相对权重 metrics-v2

`metrics.table_weights` 为三张表分别指定 `1—1000` 的整数相对权重：

```text
整体某维分数 = (wu × Su + wm × Sm + wr × Sr) / (wu + wm + wr)
```

例如三表分数为 `100、100、50`：等权是 `83.333`；users:movies:ratings 权重为 `1:1:3` 时是 `70`。`1:1:3` 与 `2:2:6` 等效。

同一组表权重用于上述四个维度，不是为五个维度各设权重，也不产生一个跨维度综合总分。整体时效性始终只取 ratings，权重为 1，不受三表权重设置影响。

只要某个必要分表分数不可计算，该维度整体也不可计算。若 users 为空但 ratings 非空，四个三表维度整体不可计算，时效性仍可计算。

报告保留浮点结果，页面以三位小数展示。前后变化是“后分数−前分数”的分数点变化：从 80 到 90 是增加 10 分，而不是相对增长 10%。

## 10. 可逐项复算的完整样例

采用初始配置。用户和电影各一条，均合法：

```text
users:  1::F::18::4::00100
movies: 1::Toy (1995)::Animation
```

评分表共七个物理行，第七行是真实空行：

| 行 | 内容 | 说明 |
| --- | --- | --- |
| 1 | `1::1::5::978307200` | 2001-01-01，合法但不在时效窗口 |
| 2 | `1::1::5::978307200` | 与第 1 行重复 |
| 3 | `1::1::9::978307200` | 同键，评分非法 |
| 4 | `1::1::4::1014940800` | 2002-03-01，在时效窗口 |
| 5 | `1::1::5::1014940800` | 与第 4 行合法同键冲突 |
| 6 | `99::1::5::1014940800` | 时间新，但用户 99 不存在 |
| 7 | 空行 | 字段数错误 |

清洗前 ratings 的计算：

| 维度 | 分子 / 分母 | 分数 | 原因 |
| --- | --- | --- | --- |
| Accurate | `5/7` | `71.429` | 第 3、7 行未通过评分检查 |
| Complete | `24/28` | `85.714` | 前六行各 4 个非空字段，空行贡献 0 |
| Unique | `3/7` | `42.857` | 第 1—3 行一个键，第 4—5 行一个键，第 6 行一个键 |
| Up-to-date | `3/7` | `42.857` | 第 4、5、6 行时间在窗口内 |
| Consistent | `0/7` | `0.000` | 第 1—3 行原始组冲突，第 4—5 行冲突，第 6 行外键错误，第 7 行结构错误 |

清洗结果：第 1 行保留，第 2 行去重，第 3—7 行隔离。核对守恒：`7 = 1 + 1 + 5`。

保留的唯一评分记录是 2001 年事件，清洗后 ratings 的 Accurate、Complete、Unique、Consistent 都为 100，时效性为 0。两个主表前后四个适用维度均为 100，因此整体结果为：

| 整体维度 | 清洗前 | 清洗后 |
| --- | --- | --- |
| Accurate | `90.476` | `100.000` |
| Complete | `95.238` | `100.000` |
| Unique | `80.952` | `100.000` |
| Up-to-date | `42.857` | `0.000` |
| Consistent | `66.667` | `100.000` |

这个例子说明：保留数据在约束上变得更干净，不保证每一个指标都上升；高分必须与保留数量、隔离原因一起看。时效性下降不一定表示清洗程序错误，也可能是较新的问题记录被排除。

## 11. 配置、结果字段与解释边界

配置可以通过自然语言或前端表单修改、保存及设为默认。可调评分参数是参照时间、窗口和三表相对权重；五维基础公式和检查项不支持任意改写。规则开关、允许事件区间和时间分区参数分别管理，不能把“评分配置”理解成任意扣分脚本。

每轮请求固定方案快照。默认设置影响后续未指定方案的请求，不重算旧报告。对比两个任务时，应先核对原始数据版本、规则、参照时间、窗口和权重是否相同。

在任务产物 `quality.json` 中可查：

| 路径 | 用途 |
| --- | --- |
| `configuration`、`config_refs`、`configuration_ref` | 本次方案快照及版本引用 |
| `before.tables.<表>.rows` / `after.tables.<表>.rows` | 前后评价行数 |
| `before.tables.<表>.metrics.<维度>` / `after.tables.<表>.metrics.<维度>` | 分表 `passed`、`population`、`score`、`status`；不适用的时效项不提供通过计数 |
| `before.overall.<维度>` / `after.overall.<维度>` | 整体 `score`、归一化 `weights`、`status` |
| `after.dispositions`、`after.reasons` | 原始输入的最终处置数量及原因次数 |
| `after.warnings`、`after.changes` | 清洗过程中原始输入的警告与变换统计 |
| `after.splits` | 保留评分在训练、验证、测试时间分区中的数量 |

`after.warnings` 不等于“清洗后仍有这些问题的记录数”：它来自原始输入的清洗处置记录，可能包含已隔离记录的警告。原因和变换次数也不能直接当作行数。完整逐条证据在 `dispositions.jsonl`。

汇总是分表分数的加权平均，不能给整体强行编造一个“通过行数 / 全部行数”。解释分数时至少同时交代配置、前后样本量、保留/隔离/去重数量，以及不可核实的事实边界。
