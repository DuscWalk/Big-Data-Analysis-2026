# MovieLens 数据清洗规则

更新日期：2026-09-30。本文按当前实现说明每种数据问题的判断与处理方式，可独立阅读。分数公式另见[质量评分计算规则](质量评分计算规则.md)。规则由小组根据课程副本制定，并非课程指定的唯一清洗方法。

文中的“默认”指仓库初始方案。网页中的共享默认可以被修改；解释某次结果时，应以该任务保存的 `configuration` 和配置版本为准。本文示例均为说明规则构造的小样本，不是全量实验统计。

## 1. 输入与输出

三张原始表无表头，按 `::` 分隔，使用 ISO-8859-1 解码：

| 表 | 原始字段顺序 | 识别同一实体或事件的业务键 |
| --- | --- | --- |
| `users` | 用户 ID、性别、年龄代码、职业代码、邮编 | `user_id` |
| `movies` | 电影 ID、标题、类型列表 | `movie_id` |
| `ratings` | 用户 ID、电影 ID、评分、时间戳 | `(user_id, movie_id, timestamp)` |

评分键包含时间：同一用户对同一电影在不同时间的评分属于不同事件，可以保留。同名电影不因此合并。年龄是数据集中的类别代码，不是具体年龄。

原始文件保持只读，每条物理记录都计入输入，包括空行和没有末尾换行的最后一行。清洗输出为 UTF-8 JSONL 三表；数值字段保存为整数，电影类型为去重并排序的字符串列表，邮编继续保存为字符串，例如 `00100` 不变成 `100`。

每条原始记录都产生处置记录，保留原字节的 Base64 表示、原始版本、文件名、行号、字节偏移、原因和修改历史。隔离表示移出可用输出，不是删除原始证据。

## 2. 处理顺序决定结果

1. 先检查原始主表和评分表，计算清洗前质量，建立原始主表存在性与冲突索引。
2. 清洗用户表和电影表：字段解析、值检查、规范化、可选隔离策略，再处理同键冲突和重复。
3. 使用清洗后的主表检查评分外键，再处理评分自身的错误、冲突和重复。
4. 对实际保留的三表重新评分，核对条数守恒、外键和文件摘要，全部通过后发布。

对每个业务键，清洗始终先排除不满足规则的候选，再比较剩余候选。不能因为同组有一条错误记录，就直接认定所有合法记录都应丢弃；剩余合法候选仍然互相冲突时，才全部隔离。

## 3. 结构与通用规则

本节 R 编号是程序中的清洗规则编号，与需求验收清单的 R 编号分别维护。

| 规则键 | 触发条件 | 实际处理 |
| --- | --- | --- |
| `R01_FIELD_COUNT` | users/movies/ratings 的字段数分别不等于 5/3/4，包括空行 | 隔离；不猜测缺失分隔符的位置，不继续解释该行字段 |
| `R02_MISSING_REQUIRED` | 字段数正确，但去掉字段首尾空白后，任一必需字段为空 | 隔离；不填补未知值 |
| `R03_TRIM` | 字段存在首尾空白 | 去除并记录原值与新值；仅此问题不会隔离 |
| `R04_IDENTIFIER` | 各表第一个 ID 不合法 | 隔离 |
| `R04_MOVIE_IDENTIFIER` | ratings 的电影 ID 不合法 | 隔离 |
| `R11_INTEGER_FORMAT` | 整数字段可明确解析，但写法不规范，如 `01`、`+5` | 转为整数并记录变化；若同时违反值域，仍隔离 |

整数解析只接受可选正负号加 ASCII 数字，原字符串长度不超过 20；不接受 `4.0`、科学计数法或非数字文本。ID 必须在 `1` 至 `9223372036854775807` 之间。最大 ID 不受本地行数或官方数据条数限制。

`R03`、`R07`、`R11` 是变换记录；其他错误仍可能使该行最终隔离。“进行过规范化”与“最后保留”必须分别判断。

## 4. 用户表规则

`R05_USER_DOMAIN` 检查以下三个约束，任一不满足即隔离：

| 字段 | 允许值 |
| --- | --- |
| 性别 `gender` | 大写 `F` 或 `M`，不自动把其他写法映射为这两类 |
| 年龄代码 `age_code` | `1、18、25、35、45、50、56` |
| 职业代码 `occupation_code` | `0` 至 `20` 的整数 |

邮编必须非空，但默认不因格式不同而隔离。`00100` 保留前导零；系统不会根据用户属性推断或补齐邮编。邮编的可选严格策略见第 8 节。

## 5. 电影表规则

标题必须非空；默认不核验片名、上映年份等事实。类型字段按 `|` 分隔，允许集合为：

```text
Action, Adventure, Animation, Children's, Comedy, Crime,
Documentary, Drama, Fantasy, Film-Noir, Horror, Musical,
Mystery, Romance, Sci-Fi, Thriller, War, Western
```

- `R06_MOVIE_GENRE`：类型字段为空，或拆分后存在不在集合中的类型，隔离。大小写严格匹配，不能把 `drama` 自动当作 `Drama`。`Drama|` 含空类型，也不合法。
- `R07_GENRE_SET`：去掉各类型条目的首尾空白、去重、排序，并记录变化。例如 `Drama|Comedy|Drama` 变为 `['Comedy', 'Drama']`。

默认保留无法核实的标题和文本，不猜测电影真实名称、不自动纠正年份、不尝试转换可疑编码。相关可选开关见第 8 节。

## 6. 评分和时间规则

| 规则键 | 触发条件 | 处理 |
| --- | --- | --- |
| `R08_RATING_DOMAIN` | 评分不是 `1—5` 的整数 | 隔离，例如 `0`、`9`、`4.5` |
| `R09_TIMESTAMP_TYPE` | 时间不是整数秒、为负，或大于 `253402300799` | 隔离；上限对应 UTC 9999-12-31 23:59:59 |
| `R10_HISTORICAL_RANGE` | 时间类型合法，但不在本任务允许的事件区间内 | 隔离；区间两端都包含 |

初始允许区间为 UTC `2000-01-01 00:00:00` 至 `2003-02-28 23:59:59`，对应 Unix 秒 `946684800—1046476799`。上下界可配置。

允许事件区间决定是否接收记录；时效参照和窗口只用于计算时效性。合法的 2000 年评分可能落在默认 365 天时效窗口之外，但不会仅因为“不够新”被隔离。时间上界是小组的历史场景约定，不是从数据最大时间戳推断出的采集截止时间。

## 7. 外键、冲突和重复

### 7.1 评分外键

每条评分必须对应保留的用户和电影。缺少任一主表实体，都不能进入清洗输出。

| 规则键 | 含义 |
| --- | --- |
| `R12_PARENT_MISSING_USERS` / `R12_PARENT_MISSING_MOVIES` | 原始主表索引中就没有对应实体 |
| `R12_PARENT_REMOVED_USERS` / `R12_PARENT_REMOVED_MOVIES` | 原始主表有该实体，但清洗主表后已移除，评分因此连带隔离 |
| `R13_PARENT_CONFLICT_USERS` / `R13_PARENT_CONFLICT_MOVIES` | 被引用的主表实体存在同键冲突，原始评分的一致性检查不通过 |

清洗评分时使用的是清洗后主表。因此原先有冲突的主表若已消解为唯一合法候选，关联评分可以保留；若实体整体被移除，则记录为 `PARENT_REMOVED`。不能将前评分的 R13 直接当作最终清洗处置。

原始主表索引按可构造的合法 ID 建立。原始某个用户虽然年龄非法，只要 ID 可用且无同键冲突，评分的“实体存在”检查仍可通过；清洗后该用户可能被移除，随后引发 R12 连带隔离。

### 7.2 合法候选优先

先按规范化后的字段比较，不以原始文本写法判断冲突。例如整数 `01` 与 `1` 相同，类型集合顺序不同也可以视作相同。

同键分组内依次处理：

1. 有字段、值域、时间、外键或已启用策略错误的记录，直接隔离。
2. 剩余合法候选存在不同属性或评分：全部隔离，原因 `R14_VALID_KEY_CONFLICT`。不取平均、不投票、不按文件先后猜真值。
3. 剩余合法候选同键同值：保留来源最早的一条，其余记 `R15_DUPLICATE` 并去重。来源顺序按文件名、字节偏移排序；当前每张表只有一个源文件，即保留偏移最小的一条。

示例假设外键和时间均合法：

| 同一评分键的候选评分 | 清洗结果 | 原因 |
| --- | --- | --- |
| `5、9` | 保留 `5`，隔离 `9` | `9` 先因值域错误移除，不污染合法候选 |
| `4、5` | 两条全部隔离 | 两个合法评分仍互相冲突，没有可靠依据取舍 |
| `5、5` | 保留来源最早的一条，另一条去重 | 同键同值 |
| `5、5、9` | 保留一条 `5`，去重一条 `5`，隔离 `9` | 先排除非法，再去重 |

同一用户、电影但时间不同的 `4` 和 `5` 不在同一键下，不触发上述冲突。

## 8. 三个可配置隔离开关

三个开关在初始方案中均关闭。关闭表示仅记警告；开启后，命中记录增加相应错误并进入隔离流程。

| 前端选项 / 配置字段 | 判断条件 | 警告键 / 开启后的规则键 |
| --- | --- | --- |
| 隔离非典型邮编 / `quarantine_zip_warnings` | 非空邮编不符合 5 位数字，或 5 位数字加连字符及 4 位数字 | `UNVERIFIED_ZIP_FORMAT` / `R16_ZIP_WARNING_POLICY` |
| 隔离缺少年份的电影标题 / `quarantine_title_warnings` | 标题末尾没有四位数字括号，例如 `(1995)` | `UNVERIFIED_TITLE_YEAR` / `R17_TITLE_WARNING_POLICY` |
| 隔离疑似混合编码的电影记录 / `quarantine_encoding_warnings` | 原始标题含非 ASCII 字符，按 ISO-8859-1 还原的字节又能按 UTF-8 解码，且得到不同文本 | `AMBIGUOUS_TEXT_ENCODING` / `R18_ENCODING_WARNING_POLICY` |

标题规则只检查末尾形式，不判断年份合理性；`(0000)` 也满足形式。编码检测只适用于原始输入的电影标题，不是通用乱码检测；它不证明哪种解码一定正确，也不会重写标题。重新评分已清洗的 UTF-8 结构化记录时，不再次进行这项原始字节探测，原警告仍保存在处置证据中。

邮编或文本不同不必然是事实错误，开启开关表示采用更严格的接收策略。隔离用户或电影还可能使相关评分被隔离，应同时查看三表处置数量。

## 9. 最终处置与统计

每条输入只属于一个最终类别：

| 类别 | 含义 |
| --- | --- |
| `kept` | 保留，没有上述业务规范化 |
| `repaired` | 保留，且执行过 R03/R07/R11 等确定性规范化 |
| `deduplicated` | 同键同值的多余记录，保存所保留记录的来源 |
| `quarantined` | 不满足规则或合法候选仍冲突，隔离并保留原因 |

有规范化历史但最后被隔离的记录，计入 `quarantined`，不再计入 `repaired`。仅将文本解析成整数或将类型转成列表，不一定产生修复标记；实际以是否记录了业务变换为准。

每张表都必须满足：

```text
输入行数 = 输出行数 + 去重行数 + 隔离行数
输出行数 = kept 行数 + repaired 行数
```

同一行可以有多个原因、警告或字段变换。原因次数之和不等于隔离行数，变换次数也不等于修复行数。质量摘要只保留每表每规则至多三条来源样例，完整证据在 `dispositions.jsonl`；样例不能当作总体统计。

## 10. 配置和结果追溯

网页“治理配置”或自然语言可以修改三个开关和时间边界，并保存方案或设为默认；基础结构、值域、外键、冲突与去重算法不可任意关闭。方案按内容版本保存，每轮请求固定所选方案，任务保存完整快照。设置默认只影响后续未指定方案的新请求，不重写旧任务。

时间分区可设置 T1/T2，要求允许下界 ≤ T1 < T2 < 允许上界；分为 `t ≤ T1`、`T1 < t ≤ T2`、`t > T2`。分区本身不移除记录，只决定后续训练、验证和测试的读取范围。

规则在 Hadoop Streaming 中执行，Agent 负责将需求转为合法配置并提交工作流，不由模型逐条判断记录或生成清洗数据。
