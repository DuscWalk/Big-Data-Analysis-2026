# 模型设置空值保存实测

日期：2026-09-27。修正清空主模型 URL 和名称后，重新打开又出现旧值的问题。

## 根因与修改

页面正确提交了空字符串，但 `ModelPreferences.prepare` 将清空 URL 也判成“更换服务地址”。存在已保存密钥、未重新填写或勾选清除时，接口返回 `422`，整份表单没有保存。实际服务当时的 `saved=false`，仍使用启动配置。隔离 API 复现也得到同一错误，说明不是保存成功后又被 `.env` 覆盖。

修正后，只有改为新的非空地址才要求重新提供或明确清除密钥。URL、模型名称可分别或同时清空；空字符串会持久保存，重启时覆盖启动配置中的旧值。缺少必需字段的服务不参与模型调用，密钥保留到用户明确清除；重新填写非空地址仍受密钥校验约束。

保存结果从面板顶部移到按钮旁，失败明确显示“未保存”，保留尚未保存的表单内容。主备服务的字段说明补充清空行为，避免把名称、地址和密钥的空值含义混淆。

## 验证

完整自动化 **133 项：131 项通过，2 项按需真实 Hadoop 测试跳过**，耗时 9.451 秒。新增 3 项 API 回归覆盖：

- 主备 URL/名称同时清空、空格规范化、立即读取和重新加载，不回退到启动值，备用配置与已有密钥保持。
- 名称或 URL 单独清空，以及明确清除密钥。
- 清空后改填新地址仍需明确处理密钥；保存、模型列表和连通性检测都不能把旧密钥送到新地址。

新增回归在修正前稳定得到 `422`，修正后通过。JavaScript 语法与 Git 差异检查通过。

隔离服务使用测试凭据，不访问真实模型。桌面 1366 px 和手机 390 px 浏览器共 7 项检查通过：主服务清空后重新打开、刷新保持空值、保存失败提示在按钮旁可见且保留草稿、拒绝更换地址后持久配置不变、手机清空备用服务、手机反馈可见且无横向溢出、无脚本错误。

## 本机应用结果

确认没有处理中消息后更新 API，通过实际页面执行用户原本的清空操作。主模型 URL、名称已保存为空，备用服务、使用方式、超时、输出上限和两份已有密钥保持不变。

实际页面重新打开、刷新均保持空值。再次重启 API 后，配置、修订标识和空字段仍保持，未从启动配置自动补回；保存文件权限为 `0600`。worker 持续运行，原有 3 个已完成任务不变。此次没有调用真实模型或提交清洗任务。
