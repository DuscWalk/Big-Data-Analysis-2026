## 4. 合并与发布核对

收尾前云端运行 `5acf41bde99e891abd14eefe8b9990797db0b420`，其[CI](https://github.com/DuscWalk/Big-Data-Analysis-2026/actions/runs/36312142734)已在 Python 3.11/3.12 上通过。收尾调整的 8 项部署测试已通过，覆盖精确提交门禁、繁忙延后、停止 API 期间的新工作、服务异常、成功发布、健康失败回退、首次失败及归档校验。

收尾按以下顺序完成发布，最终精确提交、CI 链接和核对结果保存在带注解的基线标签及服务器记录中，避免在同一提交的文档里循环写入自身 SHA：

1. 功能分支推送并等待其 CI；核对 Git 作者与提交范围，不修改历史报告或凭据。
2. 保留功能提交历史，以合并提交进入 `main`；等待该精确提交的 push CI，不能拿功能分支或 PR 的成功检查代替。
3. 显式备份并更新服务器交付器和 unit，目标改为 `main`；通过交付服务执行发布并恢复三分钟定时器。
4. 回读健康接口、四个服务状态、原样本任务的九阶段、报告下载与默认数据集；对照发布前快照核对任务/产物数量、任务/质量/报告内容以及模型配置文件摘要。
5. 成功后创建并推送不可移动的注解标签 `iteration-01-v1.0`，其中记录合并提交的 CI 和实际发布核对结论。
