# 作业三：迭代一技术与数据素材

供负责同学结合 [作业三要求](../../course/homework/作业三_大数据存储和处理与MovieLens落地架构路线图.md)开展技术比较。以下说明已经用了什么、数据在哪里、已知边界是什么；选型 T 编号及结论应接续作业二的 P/D，由两位同学讨论确定。

## 当前实际采用的技术

| 技术或方案 | 本轮用途与边界 |
| --- | --- |
| Hadoop Streaming / MapReduce + YARN | 七个真实作业完成清洗前检查与评分、清洗、清洗后检查与评分。应用负责封装、搬运和校验，不把大表交给模型处理。 |
| HDFS + 本地文件目录 | HDFS 保存封装输入、中间结果和清洗副本；原始文件及正式产物在稳定目录。当前单 NameNode、单 DataNode，副本数 1。 |
| SQLite WAL | 保存任务、阶段、产物引用、会话及调用记录，依靠唯一约束和短事务完成幂等受理与发布。单机使用，没有数据库高可用。 |
| JSONL / JSON / Markdown | 清洗三表及逐条处置使用 JSONL，指标和清单使用 JSON，报告使用 Markdown；便于审计与流式读取，尚无列式存储。 |
| FastAPI、Agent 工具层、独立 worker | 接收消息、提交异步任务、查询状态和证据、展示与下载。框架可扩展后续算法工具；目前只有一个计算 worker。 |
| ECS + systemd + GitHub CI/CD | 4 核、16 GiB 内存、100 GiB 磁盘；通过 SSH 隧道访问。main 通过 CI 后在空闲时发布，支持代码回退，同机备份不等于灾备。 |

HBase、Hive、Elasticsearch、Spark、对象存储和湖仓表格式目前均未引入。是否值得选用，应由访问需求和候选比较决定。

## 作业涉及的数据对象

| 对象 | 当前组织与访问方式 |
| --- | --- |
| 原始三表 | `.dat` 原始字节与输入指纹保留，批量扫描；不覆盖原始输入。 |
| 异常与处置 | `dispositions.jsonl` 保存来源和最终去向，包含保留、修复、去重、隔离全部处置，不能当作仅含异常的表。 |
| 清洗 users/movies/ratings | 三份 UTF-8 JSONL，按精确版本校验后流式读取；后续算法消费已发布版本。 |
| 五维质量、规则和数据版本 | `quality.json`、配置快照、`dataset-manifest.json` 及数据库中的引用；前后评分必须保持同一口径。 |
| 任务、日志与失败 | SQLite 保存应用状态和阶段；另有任务日志及 YARN 日志。外部状态不明时保留 unknown，不自动重提。 |
| 报告、样例与查询结果 | `report.md` 和质量文件保存正式结果；API 返回报告、有界样例及下载，Agent 根据这些证据解释。 |

正式产物由已登记清单确认，HDFS 清洗副本不能任意修改后反向覆盖它。当前没有统一的自动回收策略，历史数据与下游引用需要一起考虑。

原始三表约 28.4 MB；保留来源字段的清洗三表约 255 MB，共 5,895 个用户、3,836 部电影、935,354 条评分。训练/验证/测试为 746,139 / 100,814 / 88,401 条，按时间过滤同一评分文件，**没有独立的三个分区文件**。具体边界和版本见读取指南。
