# 作业二：迭代一问题素材

供负责同学结合 [作业二要求](../../course/homework/作业二_Google三驾马车与MovieLens系统架构路线图.md)整理问题与技术中立的设计决策。以下记录实验事实和现有处理方式，P/D 编号与论证留给作业完成。

## 实验背景

迭代一已实现“自然语言请求 → Agent 调用工具 → Hadoop 检查、清洗和五维评分 → 返回真实结果与解释”，也搭好了任务、会话、产物和后续工具接入的框架。后两轮算法会继续消费本轮数据。

原始 users/movies/ratings 分别为 6,946 / 4,465 / 1,150,241 行；清洗后为 5,895 / 3,836 / 935,354 行。一次本地全量治理约 12 分钟，云端目前只验证了 22 条样本的完整链路，完整清洗产物已经搬到云端。

## 实践中值得讨论的事情

| 实际情况 | 本轮怎样处理、还留下什么问题 |
| --- | --- |
| 数据包含格式错误、非法值、重复和冲突 | 保留来源及处置依据，不能判断的记录隔离。评分最终隔离 214,887 行；质量分提高伴随数据减少，不能解释成信息都被修复。 |
| 一次治理远长于普通页面交互 | 先返回任务标识，再由独立 worker 执行，页面查询真实阶段和进度。当前一个 worker，尚未验证多人并行计算。 |
| 应用中断与外部作业状态可能不同 | 运行中断后存在 unknown 任务；外部一个作业成功不代表整条流程成功。目前需核查 YARN，没有自动接续。 |
| 计算结束不等于结果可正式使用 | 校验文件、数量、外键及配置后，才共同登记产物与成功状态。实际文件与元数据并不处于一个跨系统事务中。 |
| 后续迭代容易混用数据或引入未来信息 | 产物绑定输入、规则、评分及时间配置版本；训练、验证、测试按固定历史边界读取。后续算法仍需自行防止数据泄漏。 |
| 模型可能误解问题，服务也会失败 | Agent 通过工具取证后解释；实测出现过追问解析问题及上游 504。连通性、回答切题和事实正确需要分别看待。 |
| 当前部署仍有单机边界 | 云端数据、计算和元数据在同一机器；同机备份不能抵抗整机丢失。应用会话也不等于成员权限隔离。 |

这些只是问题线索。哪些现在重要、哪些随规模变化才出现，需要结合课程机制自行判断，不必把每一行原样变成一个问题。
