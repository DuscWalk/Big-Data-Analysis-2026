## 分支与同步

`main` 保存已经验证、可供小组接手的版本。当前开发分支为 `feat/iteration-01-foundation`；后续独立功能使用有含义的 `feat/...`、`fix/...` 或 `docs/...` 分支名。

从最新主分支开始新任务前，先确认工作区内容，拉取远程引用并以快进方式同步主分支。已有未提交工作先在对应分支形成提交，避免把不同任务的更改混在一起。推送功能分支后通过评审合并到 `main`，共享分支不强制推送、不重写已发布历史。

## 自动检查与云端版本

push 和 pull request 会触发 GitHub CI，顺序检查 Python 3.11/3.12、小样本测试、前端语法及可安装包；真实 Hadoop 与模型调用不进入默认流水线。测试日志和安装包按提交 SHA 保存。

云端交付器准备为只拉取指定分支上 CI 成功的精确提交。当前发布分支暂定 `feat/iteration-01-foundation`；合并主分支后再显式切换为 `main`。部署脚本、服务器资源约束和启用状态见[华为云与 CI/CD](../deployment/README.md)。其他成员在自己的分支开发，通过评审进入选定发布分支后才更新共享环境。

## 提交范围

每个提交完成一件可审阅的事，例如文档目录整理、数据核查工具、工具注册与查询接口。提交信息采用 `docs:`、`feat:`、`fix:`、`test:` 或 `chore:` 开头，说明具体变化。

提交前检查 `git status --short`、`git diff` 和 `git diff --check`；按明确路径暂存，再通过 `git diff --cached` 核对范围。代码提交附带相应验证与使用文档，方案变更说明原因和影响。

原始数据、课件、运行目录、缓存、环境文件和凭据由 `.gitignore` 排除。可复现的源码、依赖声明、脱离数据明细也可阅读的核查报告进入仓库；大型机器结果保存在本地运行目录并登记校验值。

## 里程碑与交接

功能分支按逻辑步骤提交并同步到远程。完整验收通过、版本合并后再为正式交付创建明确的里程碑标签；设计草案和数据探索不标为实验完成版本。

每次交接给出分支、提交、环境说明、实际运行证据和未完成事项。自动生成的缓存、原始数据和本地绝对路径配置不应成为其他成员拉取代码的负担。
